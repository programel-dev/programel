## ADDED Requirements

### Requirement: Domain-based routing via Nginx
The system SHALL route incoming HTTP requests to the appropriate service based on the domain/subdomain.

#### Scenario: Main domain serves frontend
- **WHEN** a request arrives at `programel.com`
- **THEN** Nginx proxies the request to the Next.js server for SSR rendering

#### Scenario: API routing on main domain
- **WHEN** a request arrives at `programel.com/api/v1/*`
- **THEN** Nginx proxies the request to the Symfony PHP-FPM backend with the full `/api/v1/` prefix preserved

#### Scenario: Test subdomain routing
- **WHEN** a request arrives at `test.programel.com`
- **THEN** Nginx proxies to a separate set of containers (Next.js staging + API staging) running on different internal ports, using a separate staging database

#### Scenario: Subdomain routing for lebenslauf (public, no auth)
- **WHEN** a request arrives at `lebenslauf.programel.com`
- **THEN** Nginx serves static HTML files from `static/lebenslauf/` without any authentication

#### Scenario: Subdomain routing for olcha (public, no auth)
- **WHEN** a request arrives at `olcha.programel.com`
- **THEN** Nginx serves static HTML files from `static/olcha/` without any authentication

#### Scenario: Main domain requires authentication
- **WHEN** a request arrives at `programel.com` (non-public pages)
- **THEN** the Next.js app redirects unauthenticated users to the login page

### Requirement: SSL termination via Let's Encrypt
The system SHALL automatically obtain and renew SSL certificates for all domains using Certbot/Let's Encrypt.

#### Scenario: Automatic HTTPS redirect
- **WHEN** a request arrives on port 80 (HTTP)
- **THEN** Nginx redirects to port 443 (HTTPS) with a 301 status

#### Scenario: Certificate auto-renewal
- **WHEN** an SSL certificate is within 30 days of expiry
- **THEN** Certbot automatically renews the certificate without downtime

### Requirement: Security headers
The system SHALL include security headers on all HTTP responses in production.

#### Scenario: Security headers present
- **WHEN** any response is served in production
- **THEN** the response includes: `Strict-Transport-Security` (max-age=31536000, includeSubDomains), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `X-XSS-Protection: 0`, `Referrer-Policy: strict-origin-when-cross-origin`

#### Scenario: CSP header on frontend
- **WHEN** a response is served from the main domain (programel.com)
- **THEN** the response includes a `Content-Security-Policy` header restricting scripts, styles, and connections to known origins

### Requirement: Local HTTPS via mkcert
The system SHALL provide HTTPS in development using locally-trusted certificates generated by mkcert.

#### Scenario: Generate local certificates
- **WHEN** developer runs `make certs` (or equivalent)
- **THEN** mkcert generates trusted certificates for `localhost`, `programel.local`, `test.programel.local`, `lebenslauf.programel.local`, `olcha.programel.local`

#### Scenario: Dev Nginx serves HTTPS
- **WHEN** dev environment starts with generated certificates
- **THEN** Nginx serves all local domains over HTTPS (port 443) with the mkcert certificates

#### Scenario: Browser trusts local certificates
- **WHEN** developer accesses `https://programel.local` in the browser
- **THEN** no certificate warnings are shown (mkcert CA is trusted by the OS)
